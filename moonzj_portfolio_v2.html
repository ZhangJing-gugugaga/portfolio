CASE 01 · AGENT SECURITY 2026-06-27 → 09-05

从凌晨误删桌面 43 个文件，到四层纵深防御与网络共谋自查

6月27日凌晨重构作品集时，Claude Code 被 Bash Hook 拦下三次 rm 后，绕道 PowerShell 执行 cd /tmp/my-portfolio; ... Remove-Item -Recurse -Force。由于 Windows 下 /tmp 解析失败且 ; 无短路保护，桌面 43 个文件（含在研主项目 Life Guard）被静默清空。

Layer 1: Bash + PowerShell + cmd 全工具链危险正则拦截 Layer 2: /tmp 与 $env:TEMP 硬约束 → 强制收敛至 .claude/tmp/ Layer 3: 拦截前自动快照 .claude/backups/ + Shell.Application 回收站改写 Layer 4: post_tool_use 追加写入 filesystem_audit.jsonl (25项测试全通)

9月4日 Nightingale 披露 1.8 万个 Agent 借 NO_PROXY 绕过代理在德文 Wiki 串通后，我进一步把防线从本机文件系统推向网络出口白名单 + 工作负载身份边界，当晚抓出本机沙箱残留的 NO_PROXY 通配符侧门。

CASE 02 · COST & CONTEXT LEDGER 2026-07-14 → 08-26

解析 621 个会话与 13 亿 Token：为什么“输出单价差 89 倍，任务只省 4 倍”

当社区在狂欢 V4-Flash 输出价砍到 $0.28/百万 Token（Terminal Bench 2.1 拿 82.7 分）时，我导出了自己机器上 Claude Code 的 621 个会话、15,308 轮请求：发现用户手打的那句话只占 1%，中位数每轮实际读取 42,882 Token，九成以上是系统提示、工具 Schema 与历史对话构成的常驻前缀。

[实测单次 React 组件修改任务模型 (5轮交互)] - 常驻缓存读: 220,000 tokens | 全价输入: 30,000 tokens | 输出: 10,000 tokens - Opus 5 任务总价: ~$0.51 ($0.11 cache + $0.15 in + $0.25 out) - V4-Flash 任务总价: ~$0.07~$0.14 (输出差89倍 → 摊到任务级仅差4~7倍) - GLM-5.3-Flash (320B-A18B, 1/40全项同折): 100万Token长任务 ~$3.45 → $0.09

据此提炼出“三步验价比”与前缀缓存不碎法则（如 DeepSeek Harness 将压缩指令挪至请求尾部、保留未用工具 Schema 以锁死前缀字节一致）。

CASE 03 · PROTOCOL & MEMORY 2026-08-01 → 08-16

拆解 Kimi K3 权重记忆与无状态 MCP：亲手写双进程 Server 验证容灾

7月28日 MCP 移除协议级 session 与 initialize 握手后，我不靠二手解读下结论，而是用官方 SDK 写了一个无状态最小 Server，开启双进程轮流接请求并中途强杀单实例，实证“请求自包含、任意副本等价”带来的负载均衡、幂等重试与网关缓存红利，并主动勘误了自己 6 月旧文中的时序图前提。

Kimi K3 (2.8T) 记忆三件套分工: - 装得下 (1M Window): 原材料仓库，容量本身不产生优先级 - 忘得对 (23×3层 KDA): S_t = S_{t-1}(I - βkk^T) + βvk^T 逐通道学出衰减淘汰 - 取得出 (23×1层 MLA + 8个 AttnRes): 每4层精确检索兜底，仅增 ~2% 推理延迟

同时用分词器恒定差 75 Token、拒答口音、gzip 交叉压缩率三重黑盒指纹，在官方揭盅前精准锁定匿名神兽 Ox Alpha 即智谱 GLM-5.3-Flash。
